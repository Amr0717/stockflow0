# StockFlow — نظام المخزون والفواتير

تطبيق ويب خاص بك لإدارة المخزون حسب رقم الموديل (SKU) وإصدار الفواتير.
عند **إصدار** الفاتورة تُخصم الكميات من قاعدة البيانات تلقائيًا، وعند **إلغائها** تعود الكميات مرة واحدة فقط، وكل تغيير محفوظ في سجل.

- الواجهة بالعربية (من اليمين لليسار) مع زر للتحويل إلى الإنجليزية.
- تعمل على الجوال والكمبيوتر.
- البيانات محفوظة في قاعدة بيانات Supabase الحقيقية (PostgreSQL)، وليست في المتصفح.

> التقنيات: Next.js 16 + TypeScript + Tailwind CSS + Supabase (قاعدة البيانات وتسجيل الدخول) + Vercel للنشر.

---

## ماذا يوجد في المشروع؟

| المسار | المحتوى |
| --- | --- |
| `src/` | كود التطبيق (الصفحات، النماذج، الترجمة) |
| `supabase/migrations/` | ملفات SQL لإنشاء الجداول والحماية ودوال الإصدار والإلغاء |
| `supabase/seed.demo.sql` | بيانات تجريبية اختيارية (غير مفعّلة افتراضيًا) |
| `tests/` | اختبارات الأرقام، اختبارات قاعدة البيانات، واختبار المتصفح |
| `.env.example` | مثال لمتغيرات البيئة (بدون أسرار) |
| `ARCHITECTURE.md` | شرح طريقة عمل النظام ولماذا الخصم من المخزون آمن |
| `TEST-RESULTS.md` | نتائج الاختبارات التي تم تشغيلها فعليًا |

## خطوات التشغيل (بالترتيب)

### 1) المتطلبات

- حساب مجاني على [Supabase](https://supabase.com).
- حساب مجاني على [GitHub](https://github.com) و [Vercel](https://vercel.com) (للنشر على الإنترنت).
- برنامج **Node.js** الإصدار 20.9 أو أحدث (22 أو 24 يعملان) مثبت على جهازك. للتأكد اكتب في الطرفية (Terminal):

```bash
node -v
```

### 2) فك الضغط وتثبيت الحزم

افتح الطرفية داخل مجلد المشروع ثم اكتب:

```bash
npm.cmd install
```

> **مستخدمو Windows:** إذا ظهر في PowerShell خطأ مثل `npm.ps1 cannot be loaded`، اكتب `npm.cmd` بدل `npm` في **كل** الأوامر في هذا الملف (مثل `npm.cmd run dev`). على Mac أو Linux اكتب `npm` عادي.

### 3) إنشاء مشروع Supabase

1. ادخل إلى [supabase.com/dashboard](https://supabase.com/dashboard) واضغط **New project**.
2. اختر اسمًا (مثلًا `stockflow`) وكلمة مرور قوية لقاعدة البيانات واحفظها عندك.
3. اختر أقرب منطقة (Region) لك، مثل Frankfurt، ثم انتظر حتى يجهز المشروع.

### 4) تطبيق ملفات قاعدة البيانات (Migrations)

**الطريقة الأسهل (من المتصفح):**

1. في لوحة Supabase افتح **SQL Editor** ثم **New query**.
2. افتح الملف `supabase/setup.sql` من المشروع (بالمفكرة Notepad أو VS Code)، انسخ كل محتواه (Ctrl+A ثم Ctrl+C)، الصقه، ثم اضغط **Run**.
3. يجب أن تظهر رسالة **Success. No rows returned**. شغّله **مرة واحدة فقط**.

> الملف `setup.sql` هو نفس ملفي `supabase/migrations/` مدموجين بالترتيب الصحيح. يمكنك بدلًا منه تشغيل الملف الأول ثم الثاني من `supabase/migrations/`.

**طريقة بديلة (للمتقدمين، باستخدام Supabase CLI):**

```bash
npx supabase login
npx supabase link --project-ref YOUR_PROJECT_REF
npx supabase db push
```

> تأكد أن **Data API** مفعّل وأن مخطط `public` ظاهر فيه: Project Settings ← Data API (هذا هو الوضع الافتراضي).

### 5) إعداد تسجيل الدخول (Auth) ومنع التسجيل العام

التطبيق خاص بك فقط، لذلك نمنع أي شخص من إنشاء حساب بنفسه:

1. افتح **Authentication** ← **Sign In / Providers** (أو Settings).
2. أوقف خيار **Allow new users to sign up** (السماح بالتسجيل الجديد).
3. تأكد أن مزوّد **Email** مفعّل (تسجيل الدخول بالبريد وكلمة المرور).

### 6) نسخ المفاتيح إلى المشروع

1. في Supabase افتح **Project Settings** ← **API Keys** (أو زر **Connect** أعلى الصفحة).
2. انسخ **Project URL** و **Publishable key** (يبدأ عادة بـ `sb_publishable_`؛ ويمكن أيضًا استخدام مفتاح `anon` القديم).
3. في مجلد المشروع انسخ الملف `.env.example` إلى ملف جديد اسمه `.env.local`:

```bash
copy .env.example .env.local
```

(على Mac/Linux: `cp .env.example .env.local`)

4. افتح `.env.local` وضع القيم:

```
NEXT_PUBLIC_SUPABASE_URL=https://xxxx.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_xxxx
```

> ⚠️ **لا تضع أبدًا** مفتاح `service_role` أو `secret` في هذا التطبيق أو في GitHub. التطبيق لا يحتاجه.
> المفتاح العام (publishable) آمن للمتصفح لأن الحماية الحقيقية في قاعدة البيانات (RLS).

### 7) إنشاء حساب المالك (حسابك أنت)

1. في Supabase افتح **Authentication** ← **Users** ← **Add user** ← **Create new user**.
2. اكتب بريدك الإلكتروني وكلمة مرور قوية (8 أحرف أو أكثر).
3. فعّل خيار **Auto Confirm User** ثم اضغط **Create user**.

هذا هو الحساب الوحيد الذي سيدخل إلى التطبيق.

### 7.5) فحص الإعداد تلقائيًا

```bash
npm.cmd run doctor
```

هذا الأمر يفحص (بدون تغيير أي بيانات): إصدار Node، وجود `.env.local`، أن المفتاح عام وليس سريًا، أن الجداول والدوال موجودة ومحمية في Supabase، وأن التسجيل العام مغلق. إذا ظهر ❌ فالرسالة تقول لك ماذا تصلح.

### 8) تشغيل التطبيق على جهازك

```bash
npm.cmd run dev
```

افتح المتصفح على: <http://localhost:3000> وسجّل الدخول بالحساب الذي أنشأته.

### 9) (اختياري) بيانات تجريبية

إذا أردت تجربة التطبيق بمنتجات جاهزة: افتح `supabase/seed.demo.sql`، غيّر البريد `owner@example.com` إلى بريدك، ثم شغّله في **SQL Editor**.
لا تشغّله على مخزونك الحقيقي.

### 10) رفع المشروع إلى GitHub

1. أنشئ مستودعًا جديدًا **خاصًا (Private)** على GitHub باسم `stockflow`.
2. داخل مجلد المشروع:

```bash
git init
git add .
git commit -m "StockFlow first version"
git branch -M main
git remote add origin https://github.com/USERNAME/stockflow.git
git push -u origin main
```

> ملف `.env.local` لن يُرفع لأنه موجود في `.gitignore`. تأكد من ذلك قبل الرفع.

### 11) النشر على Vercel

1. ادخل إلى [vercel.com/new](https://vercel.com/new) واختر مستودع `stockflow` من GitHub ثم **Import**.
2. قبل الضغط على Deploy افتح **Environment Variables** وأضف نفس المتغيرين:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`
3. اضغط **Deploy** وانتظر حتى ينتهي.
4. انسخ رابط موقعك (مثل `https://stockflow-xxx.vercel.app`) ثم في Supabase افتح **Authentication** ← **URL Configuration** وضع الرابط في **Site URL**.

> إذا غيّرت متغيرات البيئة لاحقًا في Vercel، يجب عمل **Redeploy** حتى تُطبَّق.

### 12) تجربة سريعة بعد النشر (مهم)

1. سجّل الدخول.
2. أضف منتجًا: رقم الموديل `000123`، الكمية الافتتاحية `50`، السعر `19.95`. تأكد أن الرقم بقي `000123`.
3. أنشئ فاتورة جديدة: ابحث عن `000123`، اضغط Enter، اكتب الكمية `5`، ثم **إصدار الفاتورة** وأكّد.
4. افتح صفحة المنتج: يجب أن تكون الكمية **45** وتظهر حركة "بيع" واحدة.
5. حدّث الصفحة أو افتحها من جهاز آخر: تبقى **45**.
6. افتح الفاتورة واضغط **طباعة / حفظ PDF**.
7. اضغط **إلغاء الفاتورة** وأكّد: تعود الكمية إلى **50** وتظهر حركة "إلغاء فاتورة" واحدة.

إذا نجحت كل الخطوات فالنظام متصل بقاعدة البيانات ويعمل بشكل صحيح.

## الاستخدام اليومي

1. **المخزون**: أضف منتجاتك. لا يمكن تعديل الكمية مباشرة؛ استخدم "عملية مخزون" (توريد أو تسوية) مع كتابة السبب، فيُسجَّل كل شيء.
2. **فاتورة جديدة**: اكتب رقم الموديل ← Enter ← الكمية ← راجع الإجمالي ← **إصدار** ← **طباعة**.
3. **المسودة** لا تخصم شيئًا من المخزون. الخصم يحدث فقط عند **الإصدار**.
4. الفاتورة الصادرة لا تُعدَّل. إذا كان فيها خطأ: **ألغِها** (تعود الكميات) ثم أصدر فاتورة جديدة.
5. المنتج لا يُحذف نهائيًا إذا كان له سجل؛ يمكنك **أرشفته** فيختفي من الفواتير الجديدة.

## أوامر للمطورين

```bash
npm run dev          # تشغيل للتطوير
npm run build        # بناء نسخة الإنتاج
npm run typecheck    # فحص TypeScript
npm run lint         # فحص الكود
npm run test         # اختبارات الأرقام والمال (بدون قاعدة بيانات)
npm run test:db      # اختبارات قاعدة البيانات (تحتاج PostgreSQL محلي، انظر TEST-RESULTS.md)
npm run test:e2e     # اختبار المتصفح الكامل (يحتاج تطبيق متصل بقاعدة بيانات تجريبية)
npm run doctor       # فحص الإعداد والاتصال بـ Supabase (قراءة فقط)
npm run build:setup-sql  # إعادة توليد supabase/setup.sql بعد تعديل ملفات migrations
```

> على Windows استبدل `npm` بـ `npm.cmd`.

> اختبارات قاعدة البيانات والمتصفح تنشئ بيانات وهمية، لذلك **لا تشغّلها أبدًا على مشروعك الحقيقي**.

## مشاكل شائعة

| المشكلة | الحل |
| --- | --- |
| `npm.ps1 cannot be loaded because running scripts is disabled` | استخدم `npm.cmd` بدل `npm` (مثلًا `npm.cmd run dev`). |
| رسالة `Missing NEXT_PUBLIC_SUPABASE_URL` | لم تنشئ ملف `.env.local` أو القيم فارغة (الخطوة 6). |
| "البريد الإلكتروني أو كلمة المرور غير صحيحة" | تأكد من إنشاء المستخدم وتفعيل Auto Confirm (الخطوة 7). |
| "انتهت الجلسة" عند الحفظ | لم يتم تطبيق ملفي SQL بالترتيب، أو مفتاح خاطئ. أعد الخطوتين 4 و 6. |
| "تعذّر تحميل الصفحة" | تحقق من اتصال الإنترنت ومن أن مشروع Supabase يعمل (المشاريع المجانية قد تتوقف بعد فترة عدم استخدام؛ أعد تشغيلها من لوحة Supabase). |
| التعديلات في Vercel لا تظهر | اعمل Redeploy بعد تغيير المتغيرات. |
